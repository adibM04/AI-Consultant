# AI app builders and agent-driven development playbook

Applies to apps generated by tools such as Lovable, Bolt, Replit, v0, Cursor or Claude Code. The code usually works in a demo. The recurring gaps are what the generator was never asked to build.

Maps to: AUT-01, AUT-02, SEC-01, SEC-02, SEC-03, SEC-13, INF-01, INF-03, TST-01, TST-07, MNT-06, MNT-07, MNT-11, OPS-04, OPS-05

## AB-1 Authorisation exists on the server, not just in the UI
Maps to: AUT-01, AUT-02
- Look for: logic like `if (user.isAdmin)` that only hides buttons; the browser talking straight to the database or a backend-as-a-service with no server-side rules; admin pages guarded by a client-side redirect.

## AB-2 Prototype scaffolding has been removed
Maps to: AUT-06, SEC-15, MNT-06
- Look for: `TODO`, `FIXME`, "for now", `mock`, `dummy`, `placeholder` in non-test code; hard-coded users, admin emails, passwords or tokens; auth bypass flags; seed data and debug routes reachable in production; `console.log` of user objects.

## AB-3 Secrets that passed through a chat or a prompt are burned
Maps to: SEC-01, SEC-02
- Look for: keys in `.env` committed to git, in comments, in README setup steps, or in agent instruction files (`.cursorrules`, `CLAUDE.md`, `AGENTS.md`, `.cursor/rules`). Anything pasted into an AI tool should be treated as exposed. Rotation cannot be verified from code, so SEC-02 stays `unknown` until the founder confirms.

## AB-4 Dependencies were installed by a model
Maps to: SEC-03, SEC-04
- Use the package verifier output (`.consultant/facts/packages.json`): any `NOT_FOUND`, `TYPOSQUAT_SUSPECT`, or very new package with a tiny download count is a finding. Also look for packages that are declared but never imported, and several packages doing the same job.

## AB-5 Regeneration debris
Maps to: MNT-06, MNT-07, MNT-12
- Look for: files named `old`, `v2`, `copy`, `backup`, `final`; several implementations of the same helper (two auth utilities, three date formatters); one file that every change was appended to (list the largest files by line count); components that are exported but imported nowhere.

## AB-6 Environments and ownership
Maps to: INF-01, OPS-04, OPS-05, OPS-06
- Ask who owns the builder-platform account, the connected GitHub repo, the domain and the database project. The prototype is often tied to the creator's personal login. Check whether preview and production share a database or keys, and whether code can be exported and deployed without the builder.

## AB-7 Nothing verifies the code before it ships
Maps to: INF-03, TST-01, TST-07, MNT-11
- Look for: no CI, no tests, or tests that assert nothing (generated from the implementation, snapshot-everything, mocks of the unit under test); `// @ts-ignore`, `any`, `eslint-disable` and `noqa` counts; deploys straight from the builder to production.

## AB-8 Agents hold production credentials
Maps to: SEC-13
- Look for: production database URLs or cloud admin keys in the environment files an agent can read, agent config granting broad shell or deployment tools, one set of credentials for everything. Agents should work against dev data with credentials that cannot delete production.
